# Настройка вебинаров учебного портала

## Что уже предусмотрено

- Планирование вебинара по дисциплине и публикация для студентов.
- Вход в комнату из портала после серверной проверки доступа к дисциплине.
- Камера, микрофон, демонстрация экрана, чат, поднятие руки и список участников через Jitsi Meet IFrame API.
- Запись посещаемости по событию входа/выхода.
- Кнопка запроса записи конференции. Реальная запись доступна только если сервер Jitsi настроен на файловую запись/стриминг (например, с Jibri или соответствующей функцией управляемого сервиса).

## Обязательная настройка перед использованием с реальными студентами

Публичный \`meet.jit.si\` установлен как режим предварительной проверки. Официальный Jitsi отдельно предупреждает, что публичный сервис не предназначен для производственного использования сторонними приложениями. Не используйте этот режим для закрытых или персональных занятий.

Для запуска вебинаров в рабочем режиме разверните собственный Jitsi Meet либо подключите управляемый Jitsi-сервис с JWT authentication. В Script Properties проекта Apps Script добавьте:

- \`JITSI_DOMAIN\` — домен вашего Jitsi-сервера без \`https://\`, например \`meet.example.ru\`.
- \`JITSI_APP_ID\` — идентификатор JWT-приложения, настроенный на Jitsi-сервере.
- \`JITSI_APP_SECRET\` — секрет подписи JWT, совпадающий с настройкой сервера.

Секрет хранится только на стороне Apps Script и не передаётся браузеру. Сервер выдаёт токен на конкретную комнату и конкретного пользователя; преподаватель/администратор получает роль модератора.

Jitsi-сервер должен быть настроен на JWT-токены для всех участников и запрет гостевого входа без токена. Если сервер допускает вход без JWT, наличие токена в портале само по себе не защищает комнату.

## Запись вебинаров

Кнопка «Начать запись» вызывает команду записи Jitsi. Чтобы она работала, сервер должен иметь настроенный механизм записи (например, Jibri) либо управляемый тариф/сервис с записью. Без этого команда может быть отклонена сервером.
