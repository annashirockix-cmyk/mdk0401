# Lesson 7. Document Revisions and Configuration Control

**ID:** `en-c05-s01-l07`

### Learning outcomes
By the end of the lesson, students can explain why revision and configuration control matter; compare two document versions; describe a change without overstating its effect; identify a mismatch between references; and write a concise document-change summary.

### 1. Lead-in
Discuss in pairs:
1. What can happen if a team uses two different versions of the same drawing?
2. Is a file with the newest date always the correct file for a particular task?
3. Which information helps identify a controlled document?
4. How might a document change affect a technologist, programmer, electrician or CNC operator differently?

### 2. Key vocabulary

| English | Russian | Example |
|---|---|---|
| configuration | конфигурация, состав/состояние системы | The record identifies the training configuration. |
| configuration control | управление конфигурацией | Configuration control keeps references consistent. |
| revision | редакция, версия документа | The drawing is revision D. |
| amendment | поправка, изменение | The amendment is listed in the change record. |
| change notice | извещение об изменении | The change notice identifies the affected documents. |
| change request | запрос на изменение | A change request must be reviewed. |
| change log | журнал изменений | The change log records the date and summary. |
| baseline | базовая утверждённая версия | The baseline is identified by a reference and revision. |
| obsolete | устаревший, более не действующий | An obsolete copy must not be treated as current. |
| supersede | заменять предыдущую версию | Revision D supersedes revision C in this example. |
| affected document | затронутый документ | The notice lists each affected document. |
| impact assessment | оценка влияния | An impact assessment considers related work. |
| consistency | согласованность | The team checks consistency between references. |
| discrepancy | расхождение | The records contain a revision discrepancy. |
| approval status | статус утверждения | The approval status is shown separately. |

### 3. Reading: A revision is more than a date

Configuration control is the process of identifying and managing the characteristics and documents associated with a defined product, system or project. In a technical environment, people may use drawings, process sheets, software specifications, wiring descriptions, inspection forms and maintenance records. These documents must be identifiable and consistent with the task they support.

A revision identifier helps distinguish one version from another. A change log normally records what changed, when it changed and who or which function reviewed the change. A change notice may identify affected documents. An impact assessment considers whether related instructions, records, training materials or downstream activities also need review.

A later date does not automatically mean that a document is applicable to every situation. The correct reference is determined by the approved document-control process and the defined configuration. If two records show different revisions, the reader should record the discrepancy and request confirmation rather than choosing one.

**Fictional classroom change record**

| Field | Previous record | Updated record |
|---|---|---|
| Document | TRN-ENG-031 | TRN-ENG-031 |
| Revision | C | D |
| Issue date | 04 April 2026 | 18 April 2026 |
| Change summary | Earlier training layout | Added a document-reference field |
| Status | Superseded in this exercise | Classroom example |
| Applicability | Fictional training pack | Fictional training pack |

**Important:** the table describes a made-up training document only. It does not represent an approved aircraft drawing or an operational change.

**Comprehension**
1. What is configuration control intended to manage?
2. What information may appear in a change log?
3. What can a change notice identify?
4. Why is the latest date not sufficient by itself?
5. What should a student do when two records show different revisions?

### 4. Listening: Explaining a document change

**Before you listen**
- Predict what information a change summary should include.
- Review: *baseline, supersede, affected document, impact assessment*.
- Discuss the difference between “the document changed” and “the system changed”.

**First listening — gist. Choose one answer.**
A. A team summarizes a fictional document revision and its limits.
B. A team authorizes a modification to an aircraft.
C. A team gives instructions for changing equipment settings.

**Second listening — details**
1. What is the document reference?
2. Which revision is identified as superseded?
3. What field was added in the updated training version?
4. Does the speaker claim that an aircraft system was changed?
5. What should happen if a related document still shows the earlier revision?

**Recording script**

“Here is the change summary for training document TRN-ENG-031. The previous classroom version was revision C, issued on the fourth of April. The updated classroom version is revision D, issued on the eighteenth of April. The change adds a document-reference field to the training layout. This is a change to the training document, not a statement that an aircraft system has been modified. The change log identifies the two versions. If a related classroom record still shows revision C, note the discrepancy and ask the document owner which version is intended for the exercise. Do not select a version by date alone.”

**Transcript reveal and answer key**
- Gist: A.
- 1 TRN-ENG-031.
- 2 Revision C.
- 3 A document-reference field.
- 4 No. The speaker explicitly limits the statement to a training-document change.
- 5 Record the discrepancy and ask the document owner.

### 5. Language focus: Passive voice in change records

The passive voice is common when the action or result is more important than the person performing it:
- *Revision C was superseded by revision D.*
- *A reference field has been added.*
- *The affected documents are listed in the change notice.*
- *The discrepancy must be reviewed by the document owner.*

Compare:
- Active: “The team added a reference field.”
- Passive: “A reference field was added.”

**Practice — rewrite in the passive**
1. The document owner reviewed the change request.
2. The team added a new field to the form.
3. The change notice lists the affected documents.
4. The reviewer has not confirmed the applicability.

**Suggested answers**
1. The change request was reviewed by the document owner.
2. A new field was added to the form.
3. The affected documents are listed in the change notice.
4. The applicability has not been confirmed by the reviewer.

### 6. Guided practice

**A. Compare the versions.** Use the table in the reading. Complete:
- The document reference is…
- The previous revision was…
- The updated revision is…
- The recorded change is…
- The change does not establish…

**B. Identify the unsupported statement**
1. “Revision D is the updated version in this fictional training pack.”
2. “The change adds a reference field.”
3. “Therefore, every real aircraft using this document has been modified.”
4. “The related training record should be checked for consistency.”

**Key:** statement 3 is unsupported.

**C. Four professional routes**
- **Technologist:** compare two fictional process-sheet revisions and summarize a change to a non-operational training field.
- **Programmer:** compare two versions of a sample software requirements document; identify a changed label and a missing cross-reference.
- **Electrician:** compare fictional electrical-system vocabulary sheets; report inconsistent connector identifiers without proposing a physical action.
- **CNC operator:** compare two classroom drawing revisions; identify a changed note and state that production applicability is not established.

### 7. Speaking and writing

**Speaking — change-control meeting.** Student A presents a fictional change notice. Student B asks:
- Which document is affected?
- What changed?
- Which revision is superseded?
- Has the impact on related documents been assessed?
- What remains to be confirmed?

**Writing — change summary.** Write 130–160 words. Include the reference, previous and updated revision, change summary, affected records, unresolved question and the person/role to whom clarification is referred. Use at least three passive constructions.

### 8. Self-check

1. Configuration control helps manage:
   a) identified configurations and related information; b) personal opinions; c) file colours only.
2. A change log may record:
   a) the change, date and review information; b) unrelated attendance; c) guesses.
3. A later date alone proves applicability:
   a) always; b) not necessarily; c) only for printed documents.
4. If revisions conflict, the reader should:
   a) choose randomly; b) record the discrepancy and seek confirmation; c) delete one record.
5. “The field was added” is:
   a) passive voice; b) present perfect active; c) an imperative.

**Key:** 1a, 2a, 3b, 4b, 5a.

**Independent work:** Create a fictional change log with four entries. For each entry include a reference, revision, date, neutral summary and review status. Add a 70–90-word explanation of why a revision must be linked to applicability.

# Lesson 8. Shift Handover and Technical Correspondence

**ID:** `en-c05-s01-l08`

### Learning outcomes
Students can structure a concise technical handover; distinguish completed work, current status and pending actions; write a professional email requesting clarification; use concise linking expressions; and confirm responsibility without implying unauthorized approval.

### 1. Lead-in
Discuss:
1. What information does the next shift need?
2. Why is “everything is fine” not a sufficient handover?
3. What should be included when a task is incomplete?
4. How does a technical email differ from an informal message to a friend?

### 2. Key vocabulary

| English | Russian | Example |
|---|---|---|
| shift handover | передача смены | The handover summarizes the current status. |
| outstanding item | нерешённый / незакрытый пункт | One outstanding item requires review. |
| pending | ожидающий выполнения / решения | Confirmation is pending. |
| completed | завершённый | The classroom review is completed. |
| in progress | в процессе | The document comparison is in progress. |
| on hold | приостановленный | The exercise is on hold pending clarification. |
| follow-up | последующее действие / уточнение | A follow-up is planned. |
| action owner | ответственный за действие | The action owner is identified in the record. |
| due date | срок выполнения | The due date is stated in the task brief. |
| handover note | запись передачи информации | The handover note identifies open questions. |
| acknowledge | подтвердить получение | Please acknowledge receipt of the message. |
| clarify | уточнить | Could you clarify the applicable revision? |
| attach | прикрепить | I have attached the classroom record. |
| refer / refer to | направить / ссылаться на | Please refer the question to the document owner. |
| outstanding question | открытый вопрос | The outstanding question is listed below. |

### 3. Reading: A useful handover has a structure

A handover transfers information from one person or team to another. A useful handover is brief, factual and organized. It should identify the task or record, the current status, work already completed, outstanding items, relevant references and the next communication step.

A handover should not hide uncertainty. If a document reference is missing, a discrepancy remains unresolved or a decision is pending, the note should say so. It should also identify who is expected to clarify the matter and when a follow-up is required, if a due date has been provided.

Technical correspondence follows similar principles. A professional email normally has a meaningful subject line, a polite opening, a clear purpose, relevant context, a specific request and a courteous closing. Attachments should be named in the message, and the writer should avoid vague phrases such as “see this” or “fix it”. Acknowledging receipt confirms that a message has arrived; it does not mean that the content has been approved.

**Fictional handover note**

| Field | Classroom example |
|---|---|
| Task | Review training package TP-09 |
| Completed | Compared the two document headers |
| Current status | One revision discrepancy remains |
| Reference | TRN-ENG-031, revisions C and D |
| Outstanding item | Confirm intended classroom version |
| Action owner | Course tutor |
| Follow-up | Awaiting confirmation |

### 4. Listening: End-of-shift handover

**Before you listen**
- Look at the handover table.
- Predict which items the speaker will mention.
- Practise saying *outstanding, pending, discrepancy, acknowledge receipt*.

**First listening — gist**
A. The speaker gives a structured handover and identifies an unresolved item.
B. The speaker claims that all work is approved.
C. The speaker gives a casual social update.

**Second listening — details**
1. Which training package is being handed over?
2. What has already been completed?
3. What remains outstanding?
4. Who is expected to clarify the issue?
5. What does the speaker ask the next person to do?

**Recording script**

“This is the handover for training package TP-09. The comparison of the two document headers has been completed. One item remains outstanding: the classroom records refer to revisions C and D of TRN-ENG-031. The intended version has not yet been confirmed. The course tutor is the action owner for this clarification. Please keep the discrepancy visible in the handover note and acknowledge receipt of the message. No operational task or technical approval is being transferred; this is a classroom document-review exercise.”

**Transcript reveal and key**
- Gist: A.
- 1 TP-09.
- 2 Comparison of the two document headers.
- 3 Confirmation of the intended revision.
- 4 The course tutor.
- 5 Keep the discrepancy visible and acknowledge receipt.

### 5. Language focus: Linking expressions and concise email style

Use linking expressions to show sequence and contrast:
- *First / Next / Finally* — sequence.
- *However / Nevertheless* — contrast.
- *Therefore / As a result* — consequence.
- *In addition / Furthermore* — additional information.
- *Pending confirmation* — unresolved status.

**Email structure**
- Subject: specific and searchable.
- Opening: *Dear … / Hello …*
- Purpose: *I am writing to request confirmation of…*
- Context: reference, revision and reason.
- Request: one clear question or action.
- Closing: *Thank you for your assistance. / Kind regards,…*

**Improve the email**
“Hi. There is a problem with the files. Which one is right? Reply soon.”

**Suggested version**
“Subject: Clarification requested — training document TRN-ENG-031

Dear Course Tutor,

I am writing to request confirmation of the intended revision for training package TP-09. The two classroom records refer to revisions C and D of TRN-ENG-031. The discrepancy remains unresolved; therefore, I have kept both references in the handover note. Could you confirm which version should be used for this exercise?

Thank you for your assistance.

Kind regards,
[Student name]”

### 6. Guided practice

**A. Status language.** Classify each phrase as completed, in progress, pending or on hold:
1. “The comparison has been finished.”
2. “The review is continuing.”
3. “We are waiting for confirmation.”
4. “The exercise has been paused until the reference is clarified.”

**Key:** 1 completed; 2 in progress; 3 pending; 4 on hold.

**B. Build a handover.** Use the fictional handover note. Speak for 45–60 seconds, covering all six fields.

**C. Four professional routes**
- **Technologist:** hand over an incomplete review of a fictional process document.
- **Programmer:** hand over a software test report with one unreviewed result.
- **Electrician:** hand over a discrepancy between two classroom system descriptions.
- **CNC operator:** hand over a drawing-reference question from a training task.

### 7. Speaking and writing

**Role-play:** Student A is finishing a shift; Student B is receiving the handover. Student B must ask two clarification questions and read back one reference.

**Writing:** Write a 130–160-word professional email with a clear subject, context, one request, a status statement and a polite closing. Then turn it into a 5-line handover summary.

### 8. Self-check

1. A handover should identify:
   a) current status and outstanding items; b) rumours; c) personal criticism.
2. “Pending confirmation” means:
   a) confirmed; b) awaiting confirmation; c) cancelled permanently.
3. Acknowledging receipt means:
   a) confirming that a message was received; b) approving all its content; c) authorizing a task.
4. A useful email subject should be:
   a) specific; b) blank; c) “Hello”.
5. An unresolved discrepancy should be:
   a) recorded clearly; b) hidden; c) described as approved.

**Key:** 1a, 2b, 3a, 4a, 5a.

**Independent work:** Write a fictional handover email and a matching short handover note. The two texts must contain the same reference, status and outstanding question.

# Lesson 9. Teamwork Across Engineering Specialisms

**ID:** `en-c05-s01-l09`

### Learning outcomes
Students can explain how four engineering specialisms contribute to a shared task; distinguish discipline-specific evidence from shared project information; ask for and give clarification across professional roles; and summarize a multidisciplinary meeting.

### 1. Lead-in
A complex engineering project involves many specialists. Discuss:
1. Why does a programmer need information from an electrician?
2. Why might a technologist need to understand a CNC operator’s report?
3. What information should be shared across a team?
4. What should remain the responsibility of an authorized specialist?

### 2. Key vocabulary

| English | Russian | Example |
|---|---|---|
| interdisciplinary | междисциплинарный | The project requires interdisciplinary teamwork. |
| specialist | специалист | Each specialist contributes relevant evidence. |
| stakeholder | заинтересованная сторона | The stakeholders review the project status. |
| interface | интерфейс, точка взаимодействия | The teams discuss the interface between their records. |
| dependency | зависимость | The schedule includes a documentation dependency. |
| deliverable | результат / комплект сдаваемых материалов | The report is a project deliverable. |
| constraint | ограничение | The team records the project constraints. |
| assumption | предположение | An assumption must be identified as such. |
| evidence | фактические данные, подтверждение | Each conclusion should refer to evidence. |
| coordinate | согласовывать действия | The specialists coordinate their reports. |
| responsibility | ответственность | Responsibilities are agreed at the meeting. |
| escalate | передавать вопрос на более высокий уровень | The unresolved issue is escalated. |
| cross-check | сверять, проверять взаимно | The teams cross-check document references. |
| feedback | обратная связь | The programmer provides feedback on the data format. |
| common understanding | общее понимание | A read-back helps establish common understanding. |

### 3. Reading: One project, four perspectives

Consider a fictional classroom project about preparing a technical information pack for a training aircraft component. The project is not a real aircraft task. It requires contributions from four specialisms.

**The technologist** explains the sequence of manufacturing stages in a process overview. The technologist identifies the source and revision of the classroom process sheet and explains which information is still missing.

**The programmer** describes the structure of a fictional data file and explains how sample records are labelled. The programmer distinguishes an observed data-format issue from a possible explanation.

**The electrician** explains general electrical terminology used in the training pack and identifies a mismatch between two fictional system-description labels. The electrician does not infer a real circuit condition from the classroom documents.

**The CNC operator** explains the meaning of drawing references, feature identifiers and sample measurement records. The operator reports missing information without proposing a machine adjustment.

The team has one shared responsibility: communicate clearly and keep the project information consistent. However, shared communication does not remove professional boundaries. A specialist should not approve another specialist’s work without the appropriate competence and authority. The team should record assumptions, identify dependencies and escalate unresolved questions to the responsible person.

**Fictional project board**

| Role | Contribution | Evidence / deliverable | Open question |
|---|---|---|---|
| Technologist | Process overview | Training process sheet TP-12, rev A | Is the material note complete? |
| Programmer | Data-format summary | Sample data dictionary DD-03, rev B | Is the field name consistent? |
| Electrician | Terminology review | Classroom system glossary EG-02, rev A | Which label is intended? |
| CNC operator | Drawing and measurement vocabulary | Training drawing DR-08, rev C | Is the feature identifier shown? |

### 4. Listening: Multidisciplinary project meeting

**Before you listen**
- Review the four roles in the project board.
- Predict which issue might require coordination.
- Practise the phrases *from my perspective, according to the record, this remains an assumption, could you clarify…*

**First listening — gist**
A. Four specialists share the status of a fictional information pack and identify open questions.
B. One specialist gives instructions to operate a machine.
C. The team approves an aircraft for service.

**Second listening — details**
1. What does the technologist need to clarify?
2. What issue has the programmer noticed?
3. What mismatch has the electrician identified?
4. What information is missing from the CNC operator’s drawing example?
5. What does the team agree to do with unresolved questions?

**Recording script**

“Let us review the training information pack. The technologist has prepared the process overview, but the material note still needs clarification. The programmer has found that one sample data field uses a different label in the summary. The electrician has identified two different labels in the classroom system glossary; the intended wording is not confirmed. The CNC operator has checked the training drawing and reports that the feature identifier is missing from the example. These are four separate observations, not one confirmed technical fault. We will list each source, keep the questions open and refer them to the relevant document owners. Before closing the meeting, each person will read back their action.”

**Transcript reveal and key**
- Gist: A.
- 1 The material note.
- 2 One sample data field has a different label in the summary.
- 3 Two labels differ in the classroom system glossary.
- 4 The feature identifier.
- 5 Record each question and refer it to the relevant document owner.

### 5. Language focus: Reporting perspective and avoiding overgeneralization

Useful phrases:
- *From the technologist’s perspective…*
- *According to the sample record…*
- *The available information indicates…*
- *This observation does not establish…*
- *The issue appears to be related to…* (tentative)
- *Could the document owner clarify…?*
- *The team agreed that…*

Avoid presenting one person’s observation as a confirmed project-wide conclusion.

**Combine the statements**
1. The programmer found a different field label. The programmer did not confirm the cause.
2. The electrician identified two terms. The glossary owner must confirm the intended term.
3. The CNC operator found a missing identifier. The drawing example is fictional.

**Suggested answers**
1. The programmer found a different field label, but the cause has not been confirmed.
2. The electrician identified two different terms, and the glossary owner must confirm the intended wording.
3. The CNC operator found a missing identifier in the fictional drawing example.

### 6. Guided practice

**A. Match the contribution to the role**
1. Summarizes the sample data structure.
2. Explains the process sequence.
3. Reviews electrical terminology in the classroom glossary.
4. Describes drawing references and sample measurement records.

a. CNC operator; b. electrician; c. programmer; d. technologist.

**Key:** 1c, 2d, 3b, 4a.

**B. Meeting language — choose a professional response**
1. You do not understand another specialist’s abbreviation.
   a) Pretend you understand. b) Ask for clarification. c) Replace it with your own guess.
2. Another specialist reports an observation outside your area.
   a) Record the source and refer the issue to the responsible specialist. b) Approve it yourself. c) Ignore it.
3. Two reports conflict.
   a) Hide one report. b) Record both references and request a cross-check. c) Select the more convenient result.

**Key:** 1b, 2a, 3b.

**C. Four professional routes — rotating roles**
In groups of four, each student takes one professional role. Prepare one fact, one piece of evidence, one limitation and one question. Exchange information and produce a common project status summary.

### 7. Speaking and writing

**Speaking — project meeting.** Conduct a four-person meeting using the project board. Each student must:
- state their contribution;
- cite one source;
- identify one open question;
- ask another specialist for clarification;
- read back one agreed action.

**Writing — meeting minutes.** Write 150–180 words with:
- meeting purpose;
- contributions from all four roles;
- evidence and references;
- decisions actually agreed;
- unresolved questions;
- action owners.

Do not write that a matter is “approved” unless the case explicitly says so.

### 8. Self-check

1. Interdisciplinary teamwork involves:
   a) specialists sharing relevant information; b) one person doing every task; c) removing all role boundaries.
2. An assumption should be:
   a) identified as an assumption; b) presented as a fact; c) hidden.
3. A dependency is:
   a) a relationship in which one task or result relies on another; b) a personal opinion; c) a synonym for approval.
4. If an issue is outside your competence or authority, you should:
   a) approve it anyway; b) refer or escalate it appropriately; c) invent an answer.
5. Meeting minutes should record:
   a) evidence, agreed actions and open questions; b) rumours; c) unsupported conclusions.

**Key:** 1a, 2a, 3a, 4b, 5a.

**Independent work:** Prepare a one-page fictional team status report with four role contributions, one shared dependency, two unresolved questions and an action owner for each question.

# Lesson 10. Interpreting Drawings, Tables and Trend Charts

**ID:** `en-c05-s01-l10`

### Learning outcomes
Students can identify common chart and table features; describe trends, comparisons and exceptions; distinguish correlation from causation; summarize fictional technical data with appropriate units and qualifications; and write a short evidence-based interpretation.

### 1. Lead-in
Discuss:
1. Why are tables and charts useful in technical communication?
2. What information should appear in a chart title and axis labels?
3. Can a trend chart by itself prove why a change occurred?
4. Why must a reader check units, dates and data source?

### 2. Key vocabulary

| English | Russian | Example |

| horizontal axis | горизонтальная ось | Time is shown on the horizontal axis. |
| vertical axis | вертикальная ось | The vertical axis shows the fictional index. |
| data point | точка данных | Each data point represents one sample. |
| data series | ряд данных | The chart contains two data series. |
| trend | тенденция | The trend is generally upward. |
| fluctuate | колебаться | The values fluctuate slightly. |
| peak | пик, максимальное значение | The series reaches a peak in Week 4. |
| dip | снижение, спад | There is a small dip in Week 5. |
| steady | стабильный, равномерный | The first series remains relatively steady. |
| increase / rise | увеличиваться / рост | The value rises from Week 1 to Week 3. |
| decrease / fall | уменьшаться / снижение | The second value falls slightly. |
| remain unchanged | оставаться без изменений | The value remains unchanged. |
| exceed | превышать | Series A exceeds Series B in Week 3. |
| approximately | приблизительно | The value is approximately 12 units. |
| outlier | выброс, нетипичное значение | One point appears to be an outlier. |
| correlation | корреляция, взаимосвязь | Correlation does not prove causation. |
| source | источник | The source is stated below the chart. |
| sample size | объём выборки | The sample size is limited. |
| limitation | ограничение | The report identifies the data limitations. |

### 3. Reading: Read the chart, not your assumptions

A technical chart is useful only when the reader understands what it represents. Before describing a trend, check the title, axes, units, time period, legend and data source. A chart without units or a clear source may be difficult to interpret.

A **trend** describes the general direction of a series. Values may rise, fall, remain steady or fluctuate. A **peak** is a high point; a **dip** is a local decrease. An **outlier** is a point that differs noticeably from the general pattern and may require further review.

A chart can show that two values changed at the same time. It does not automatically prove that one change caused the other. Correlation is not causation. A responsible report describes what the data show, notes limitations and avoids unsupported explanations.

**Fictional classroom dataset — not an aircraft performance or acceptance dataset**

The following values are invented for language practice. “Index units” are arbitrary classroom units, not volts, amperes, temperatures, vibration limits or real engineering measurements.

| Week | Series A (index units) | Series B (index units) |
|---|---:|---:|
| 1 | 10 | 8 |
| 2 | 11 | 9 |
| 3 | 13 | 9 |
| 4 | 14 | 10 |
| 5 | 12 | 11 |
| 6 | 13 | 10 |

**Observations that can be supported**
- Series A rises from 10 to 14 between Weeks 1 and 4.
- Series A then falls to 12 in Week 5 and rises slightly in Week 6.
- Series B rises gradually from 8 to 11 by Week 5, then falls to 10.
- Series A is higher than Series B in every listed week.
- The dataset alone does not explain why either series changes.

**Comprehension**
1. Which series reaches its highest value in Week 4?
2. In which week does Series B reach its highest value?
3. What happens to Series A between Weeks 4 and 5?
4. Which series is higher in Week 6?
5. Can the table prove the cause of the changes? Why or why not?

### 4. Listening: Presenting a trend chart

**Before you listen**
- Review *rise, fall, fluctuate, peak, approximately, source, limitation*.
- Predict which details a presenter should mention before interpreting the trend.
- Remember that the values are arbitrary classroom index units.

**First listening — gist**
A. The speaker describes two fictional data series and identifies limits on interpretation.
B. The speaker explains how to measure an aircraft system.
C. The speaker confirms the cause of a real equipment failure.

**Second listening — details**
1. What happens to Series A from Week 1 to Week 4?
2. What happens to Series A in Week 5?
3. When does Series B reach its highest value?
4. Which series is higher in Week 6?
5. Does the speaker identify a cause for the changes?

**Recording script**

“This chart presents two fictional data series over six weeks. The horizontal axis shows the week number, and the vertical axis shows arbitrary index units. Series A rises from ten units in Week 1 to a peak of fourteen in Week 4. It then falls to twelve in Week 5 before increasing slightly to thirteen. Series B increases more gradually and reaches eleven units in Week 5, then falls to ten. Series A remains above Series B throughout the period. The chart describes the pattern, but it does not explain the cause. The source is a classroom dataset, and the values must not be interpreted as real engineering measurements.”

**Transcript reveal and key**
- Gist: A.
- 1 It rises from 10 to 14.
- 2 It falls to 12.
- 3 Week 5.
- 4 Series A.
- 5 No. The cause is not identified.

### 5. Language focus: Describing trends and making cautious comparisons

Useful structures:
- *The value increased from 10 to 14.*
- *The series rose by 4 units.*
- *There was a slight decrease in Week 5.*
- *The value remained stable between…*
- *Series A was higher than Series B.*
- *The data appear to show…*
- *The chart does not establish the reason for…*

Be precise:
- **from 10 to 14** = starting and ending values;
- **by 4 units** = size of the change;
- **to 14** = final value;
- **approximately 14** = an estimate.

**Practice**
1. Series A changes from 10 to 14. Describe the change using *from…to…*
2. Series B changes from 8 to 11. Describe the increase using *by…*
3. Series A falls from 14 to 12. Describe the change.
4. Complete: “The chart shows a correlation; however, it does not ______ causation.”

**Suggested answers**
1. Series A increased from 10 to 14.
2. Series B increased by 3 units.
3. Series A fell by 2 units, from 14 to 12.
4. prove.

### 6. Guided practice

**A. Table reading**
1. Identify the title and units (the dataset description above).
2. Identify the highest value in Series A.
3. Identify the lowest value in Series B.
4. Compare both series in Week 6.
5. Write one limitation of the dataset.

**Key:** 1 two fictional series over six weeks, arbitrary index units; 2 14 in Week 4; 3 8 in Week 1; 4 A=13 and B=10, so A is higher; 5 values are fictional, sample is small and no causal information is provided.

**B. Choose a defensible statement**
1. “Series A reaches 14 index units in Week 4.”
2. “A damaged aircraft component caused the Week 5 dip.”
3. “Series B reaches 11 index units in Week 5.”
4. “The two series prove that one system controls the other.”

**Key:** 1 and 3 are supported; 2 and 4 are unsupported.

**C. Four professional routes**
- **Technologist:** describe a fictional table showing the number of training records completed each week.
- **Programmer:** describe a sample software-test chart using arbitrary counts, and state the sample-size limitation.
- **Electrician:** interpret a fictional glossary-completion chart; do not treat index units as electrical readings.
- **CNC operator:** describe a fictional drawing-review progress table; do not interpret it as machining tolerance data.

### 7. Speaking and writing

**Speaking — one-minute chart report.** State the title and units, describe two trends, identify one comparison and one limitation. Do not invent a cause.

**Writing — data commentary.** Write 140–170 words:
- introduce the chart and source;
- describe Series A;
- describe Series B;
- compare the series;
- identify one limitation;
- finish with a cautious conclusion.

### 8. Self-check

1. The horizontal axis usually runs:
   a) left to right; b) top to bottom; c) diagonally only.
2. A peak is:
   a) a high point; b) a source note; c) a unit label.
3. “The value increased by 3 units” describes:
   a) the size of the change; b) the final value only; c) the time period.
4. Correlation automatically proves causation:
   a) yes; b) no; c) only in a table.
5. Before interpreting a chart, check:
   a) title, axes, units and source; b) only the colour; c) the author’s opinion.

**Key:** 1a, 2a, 3a, 4b, 5a.

**Independent work:** Choose or invent a small non-operational dataset with 5–7 rows. Give it a title, units, source note and two series. Write a 120-word interpretation that includes one trend, one comparison, one limitation and no unsupported causal claim.

### C. Integrated listening — Cross-team status briefing

**First listening — gist:** A team summarizes the status of a fictional information pack.

**Second listening — details**

2. Which two professional roles have supplied information?

### D. Integrated writing — Technical information pack status report

Write 180–220 words for a fictional multidisciplinary project meeting. Your report must:
- identify the document reference and revision;
- summarize contributions from at least three professional roles;
- describe one chart or table observation;
- distinguish completed work from pending items;
- identify one dependency;
- assign a follow-up to an appropriate role;

**Assessment rubric — 12 points**
