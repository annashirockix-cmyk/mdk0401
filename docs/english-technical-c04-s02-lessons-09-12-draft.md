# Lesson 9. Avionics Overview: Systems and Information Exchange

**ID:** `en-c04-s02-l09`  
**Learning outcomes.** By the end of the lesson, students can:
- explain in simple technical English what avionics means;
- identify broad groups of onboard electronic systems;
- describe information exchange between sensors, computers, displays and communication equipment;
- distinguish a system, a component, an input, a process and an output;
- summarize a short technical briefing and ask for clarification.

### 1. Lead-in: What is avionics?

Discuss:
1. What electronic systems can be found on a modern aircraft?
2. Why do different systems need to exchange information?
3. What is the difference between a sensor and a display?
4. Which specialists may work with the same technical information?

**Key idea.** *Avionics* is a broad term for electronic systems used in aircraft. Depending on the aircraft and its certification, these may include communication, navigation, monitoring, flight-management, indication and other systems. This lesson introduces vocabulary and system relationships; it does not describe how to operate or maintain any particular aircraft.

### 3. Reading: A simplified information chain

In a simplified training model, a sensor produces a signal related to a physical condition. An electronic unit receives the signal and converts it into information that can be processed. A computer may compare the information with other data and prepare an output. The output can be sent to a display, stored in a record or shared with another system through an interface.

The information chain is not always a straight line. A system may receive information from several sources, check whether the data is available and valid, and send status information back to another unit. Some aircraft architectures include independent or redundant elements. The actual design depends on the aircraft type and its approved technical documentation.

Different specialists may use the same information for different purposes. An electrician may study terminology in a wiring or system description. A programmer may examine data formats and software messages. A technologist may use configuration and production records. A CNC operator may read the approved digital drawing or revision information for a component. Each person must work within their role and authorization.

**Comprehension**
1. What does a sensor provide?
2. What may a processing unit do with incoming information?
3. Name three possible destinations for an output.
4. Why can the information chain be more complex than a straight line?
5. How may four engineering specialisms use related information differently?

# Lesson 10. Programming Logic, Flowcharts and Algorithms

**ID:** `en-c04-s02-l10`  
**Learning outcomes.** Students can:
- define an algorithm as a sequence of steps for solving a problem;
- recognize sequence, selection and iteration;
- read a simple flowchart and describe it in English;
- use conditionals and sequencing language;
- discuss how programmers and other specialists describe a process.

### 1. Lead-in

Discuss:
1. What instructions do you follow when you complete a familiar classroom task?

3. Can a computer make a decision? What information does it need?

| condition | условие | The program checks a condition. |

| input data | входные данные | The program receives input data. |
| process | обрабатывать; процесс | The system processes the input. |
| output | результат, выходные данные | The output is displayed. |
| valid / invalid | допустимый / недопустимый | The program checks whether the value is valid. |
| threshold | пороговое значение | The example uses a fictional threshold. |
| error message | сообщение об ошибке | An error message explains the problem. |
| branch | ветвь алгоритма | The condition selects a branch. |
| test case | тестовый случай | A test case checks one situation. |

### 3. Reading: Three basic structures

An algorithm is a finite and ordered description of steps used to complete a task or solve a problem. A simple algorithm may contain three basic structures.

**Sequence** means that instructions are performed one after another. For example: receive a file, check its name, and save a copy.

**Selection** means that the next step depends on a condition. A program may ask: “Is the file format valid?” If the answer is yes, it continues. If the answer is no, it displays a message.

**Iteration** means that one or more steps are repeated. A program may review each item in a list until all items have been checked.

Flowcharts use conventional shapes to represent processes. In a basic classroom diagram, an oval often marks the start or end, a rectangle represents a process, a diamond represents a decision, and arrows show the direction of flow. Symbols and conventions can vary between standards and software tools, so students should follow the notation specified for their course or project.

A good algorithm is clear, finite, testable and appropriate for the problem. It should define what happens when data is missing, invalid or outside the expected range. Programmers need this precision. Technologists may use process flowcharts to explain manufacturing stages. Electricians may read simplified logic diagrams in training materials. CNC operators may follow a documented sequence for a simulated task, while actual machine operation remains governed by approved procedures and supervision.

### 5. Language focus: Conditionals and process verbs

**Zero conditional** describes a general rule:  
`If + Present Simple, Present Simple`  
*If the format is invalid, the program displays a message.*

**First conditional** describes a possible future result:  
`If + Present Simple, will + verb`  
*If the test fails, the team will review the test record.*

Useful process verbs: *receive, check, compare, select, repeat, record, display, reject, continue*.

Complete:
1. If the input ______ (be) missing, the program displays a warning.
2. If the value is valid, the process ______ (continue).
3. If the test fails, the operator ______ (record) the result.
4. The loop ______ (repeat) the check for every item.

**Key:** 1 is; 2 continues; 3 records / will record (depending on the intended meaning); 4 repeats.

### 3. Reading: From a reading to a reliable report

A sensor may produce a series of readings. A digital system can attach a timestamp and an identifier to each record. Before the information is used, a validation process may check whether required fields are present, whether the format is correct, whether records are duplicated and whether values fall within the range defined for the particular exercise.

Validation does not automatically prove that a physical component is faulty or healthy. It only tells the analyst whether the data meets the selected checks. A value outside a training range may be caused by a simulated event, a data-entry problem, a sensor issue or another factor. More evidence may be needed before a conclusion is reached.

A diagnostic log is a chronological record of events, messages or status changes. A useful report separates facts from interpretations. Compare:

- **Observation:** “Record 014 contains no value in the temperature field.”
- **Unsupported conclusion:** “The sensor is broken.”
- **Careful interpretation:** “The missing field requires review. The available record does not identify the cause.”

This distinction matters across all four professional routes. Electricians may need clear descriptions of recorded status information. Programmers may examine data structure and validation results. Technologists may compare process records and revision identifiers. CNC operators may read measurement records and identify incomplete entries. In every case, reports should state what was observed, where the evidence came from and what remains unknown.

### 3. Reading: Identity, permission and responsible handling

Cybersecurity is not only a technical issue. It also depends on people, procedures and responsible decisions. In an organization, access control helps ensure that users can reach only the resources needed for their roles.

Three terms are important. **Authentication** checks who a user is. **Authorization** determines what that user is permitted to do. **Access control** is the broader process of managing access to systems and information. A person may successfully sign in but still not have permission to open a particular file.

Social engineering uses deception to persuade people to reveal information or perform an action. A phishing message may create urgency, imitate a familiar organization, contain an unexpected attachment or ask the recipient to follow an unusual link. The safest response is to follow the organization’s approved reporting procedure. Staff should not forward confidential information to personal accounts or attempt to investigate a suspected incident outside their role.

The same principles apply across engineering specialisms. Electricians may encounter controlled technical records. Programmers may work with source code, test data and user permissions. Technologists may handle process sheets and supplier information. CNC operators may use controlled drawing revisions and production records. Staff should use authorized accounts, protect confidential information, follow approved update procedures and report suspicious activity.

4. Why should a suspected incident be reported through an approved channel?

- `must not` — prohibition: *You must not share your password.*
- `should` — advice: *You should report a suspicious message.*
- `do not have to` — no obligation: *You do not have to open an unexpected attachment.*

Be careful: *must not* means “нельзя”; *do not have to* means “не обязательно”.

Choose the correct form:
1. Staff ______ share their passwords. (must not / do not have to)
2. You ______ report a suspicious message. (should / must not)
3. Users ______ follow their role-based permissions. (must / must not)
4. You ______ open every attachment you receive. (do not have to / must)

**Key:** 1 must not; 2 should; 3 must; 4 do not have to.

### 6. Guided practice

**A. Authentication or authorization?**
1. Checking a user’s identity.
2. Deciding whether a user may edit a file.
3. Confirming a sign-in attempt.
4. Defining access rights for a role.

**Key:** 1 authentication; 2 authorization; 3 authentication; 4 authorization.

**B. Identify warning signs**  
Read the fictional message:

“URGENT! Your technical account will be deleted in 10 minutes. Open the attached file and send your password to confirm your identity.”

List at least three warning signs. Do not open or interact with any real suspicious attachment or link.

**Suggested answer:** artificial urgency; unexpected attachment; request for a password; threatening language; unusual identity-verification method.

**C. Four professional routes**
- Electricians: explain why access to controlled system records must be role-based.
- Programmers: describe why test accounts and production accounts should not be confused.
- Technologists: explain why process and supplier documents may be confidential.
- CNC operators: explain why the correct drawing revision and approved file source matter.
